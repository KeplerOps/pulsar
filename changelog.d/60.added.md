Workbench-graph validation CI gate — PUL-P002 / ADR-008 #7. The
canonical workbench scene/composition declarations move from
`src/main.ts` inline literals to a new module
`src/workbench-graph.ts` (`WORKBENCH_SCENES` /
`WORKBENCH_COMPOSITIONS`). The module lives at the composition-root
layer (next to `main.ts`), not inside `src/runtime/`, so the runtime
engine layer stays app-agnostic and does not import concrete scenes
or compositions. Both `src/main.ts` and the new
`tests/runtime/workbench-graph.test.ts` import from this single
source, so the bootstrap PUL-F028 validation and the CI gate run
against identical inputs. The new test calls `validateRuntime` over
the registered graph and asserts zero findings — a non-empty findings
array surfaces every finding's code + message and fails the test,
turning every PUL-F028 finding class (missing cleanup, dangling
asset, duplicate id, unknown scene reference, malformed composition
manifest) into a hard CI gate via the existing Vitest run. A second
test stanza appends a deliberately broken scene next to the real
graph and confirms the validator still surfaces findings, proving
the gate fails on broken input rather than relying on reviewer
inspection. No new CI job, no new package script, no new dev
dependency — the gate reuses the existing `test` job in
`.github/workflows/ci.yml` per the PUL-P002 architecture preflight's
"no parallel workflow controller" guardrail. The canonical-graph
module is the extensibility seam for a future `pnpm validate` CLI
or JSON drift report layered on the same import.
