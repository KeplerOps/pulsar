PUL-A009 captions / prompter single-source gate. The constraint
(`The prompter view SHALL be derived from the same caption metadata
used by the runtime. There SHALL NOT be a separate authoring source
for prompter content.`) is now structurally pinned by a Vitest
source-policy scan, defense in depth on top of the existing
`Caption` / `SceneModule.captions` / `buildPrompterScript()` seam.
  - New `tests/runtime/policy-a009-captions-single-source.test.ts`
    Vitest scan with four sub-rules:
    - Forbid property AND method declarations named
      `prompterCaptions`, `prompterScript`, `prompterText`,
      `teleprompter`, `captionOverrides`, `script`, or `notes` on
      the `SceneModule` interface (`src/runtime/scene.ts`) or the
      `CompositionEntryOverride` interface (`src/runtime/composition.ts`).
      Property-name extraction covers identifier, string-literal,
      and computed-string-literal forms so a `['prompterCaptions']:
      ...` member cannot escape. Method-style members
      (`script(ctx): void`) are also flagged.
    - Forbid parallel caption-schema declarations across every
      binding shape (`interface`, `type`, `const`, `let`, `var`,
      `class`, `function`, `enum`, destructured-binding, import,
      for-loop-header) anywhere under `src/**/*.ts`. Forbidden
      names: `Caption`, `PrompterCaption`, `PrompterCaptionSchema`,
      `CaptionSchema`, `CaptionError`, `CaptionAuthoring`,
      `PrompterAuthoring`, `CaptionInput`, `CaptionDTO`. `Caption`
      itself is included with a path-AND-kind-sensitive exemption:
      only `interface Caption` and `type Caption = ...` are allowed
      at `src/runtime/scene.ts`; value-level `Caption`
      (`const Caption = ...`, `class Caption`, etc.) is flagged
      even at the canonical path. Consumer-side imports of `Caption`
      whose specifier path-resolves to the canonical declaration
      site are exempt; imports from any other path are flagged. The
      derived `PrompterScript` / `PrompterScriptEntry` /
      `PrompterRenderer` / `PrompterDispose` output types are
      intentionally outside the forbidden set.
    - Require `src/runtime/prompter.ts` to import `Caption` only
      from `./scene`. The rule flags four import shapes that bring
      `Caption` into prompter's identifier scope from a
      non-canonical specifier: named imports (source or local name
      = `Caption`), default imports bound locally as `Caption`,
      and namespace imports bound locally as `Caption`.
    - Forbid the same caption-authoring field AND method names on
      scene-module and composition-entry object literals (the actual
      authoring surface under `src/scenes/**/*.ts` and
      `src/compositions/**/*.ts`). `assertSceneModule()` accepts
      unknown keys, so the structural defense lives in source policy.
      Binding-shape detection covers: direct `: SceneModule` /
      `as SceneModule` / `satisfies SceneModule` / legacy type
      assertion; composition-manifest array entries
      (`const m: CompositionManifest = [{ id, script }]`); function-
      return SceneModule (`function makeScene(): SceneModule { return
      {...} }` and arrow `(): SceneModule => ({...})`); intersection
      types (`SceneModule & Extra`); and file-local aliases
      (`import { SceneModule as Module }`, `type Module = SceneModule`,
      chained type aliases). Spread assignments (`{ ...extra }`) and
      opaque computed keys (`{ [key]: ... }` where `key` is not a
      static literal) inside a scene-shaped literal are structurally
      banned because their forbidden-field content cannot be
      statically classified.
  - Line-scoped `// PUL-A009-allow: <reason>` exemptions are honored
    via the shared `collectLineExemptions` helper. Empty rationales
    and markers hidden inside string literals are rejected.
  - No production source change: the runtime already routes prompter
    content exclusively through `SceneModule.captions` and
    `buildPrompterScript()`; the gate locks the invariant in.
  - References: ADR-008 #9 (one source for prompter and presenter
    views), ADR-022 (`mode=prompter` data path), and the design
    preflight at
    `docs/design/pul-a009-captions-prompter-single-source-preflight.md`.
