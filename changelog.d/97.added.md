Issue 97 — browser-level runtime smoke/e2e coverage. The ADR-030 /
PUL-Q002 Playwright matrix (chromium / firefox / webkit) now also
runs `tests-e2e/runtime-smoke.spec.ts`, which proves the workbench
boots, dispatches the URL grammar, and renders meaningfully across
three additional scenarios issue 97 named that the prior specs did
not cover:
  - **Default route** (`/`): `#stage` mounts, the bootstrap-applied
    `data-pulsar="placeholder"` marker is set, PUL-F028 validation
    succeeds, the URL parser accepts the empty search string, the
    `kind: 'none'` locator does NOT mount a scene, and the PUL-F031
    chrome surface mounts with `data-pulsar-chrome-visibility="visible"`
    under effective `mode=present`.
  - **Composition route** (`?composition=default&mode=paused`): the
    composition resolver writes BOTH `data-pulsar-composition-target`
    and `data-pulsar-scene-target` on `#stage`, the resolved scene
    (placeholder) reaches its `timeline` lifecycle phase, and
    `mode=paused` holds it there durably.
  - **Mode-specific + screenshot blank-stage**
    (`?scene=browser-support-fixture&mode=loop`): the fixture element
    is a descendant of `#stage` with a non-zero bounding box, the
    GSAP timeline advances `data-pulsar-fixture-state` to `"ran"`,
    and the element-level `#stage` PNG screenshot differs
    byte-for-byte from the default-route's `#stage` screenshot taken
    in the same engine — the mechanical blank-stage regression
    guard. Each test injects a minimal harness stylesheet via
    `page.addStyleTag()` so `#stage` and the fixture element have
    visible dimensions for the screenshot operation; no baseline
    snapshots are committed and no production CSS is added.

  No runtime, scene, composition, registry, or workflow changes. The
  new spec is discovered by the existing `pnpm test:browsers` command
  and the existing `browser-support` CI job. The PUL-Q002 source-policy
  Vitest gate is unchanged.
