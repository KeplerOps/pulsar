### Added

- PUL-A010 live-and-export shared scene metadata gate. The constraint
  (`Any export pipeline SHALL consume the same scene metadata and
  composition manifests as the live runtime. Export-specific metadata
  SHALL NOT replace live-runtime metadata.`) is now structurally
  pinned by a Vitest source-policy scan, defense in depth on top of
  ADR-006 (Remotion as a parallel export path), PUL-A004's runtime-
  core import ban on Remotion, and the single declaration sites for
  `SceneModule` (`src/runtime/scene.ts`) and `CompositionManifest` /
  `CompositionEntry` / `CompositionEntryOverride`
  (`src/runtime/composition.ts`).
  - New `tests/runtime/policy-a010-export-metadata-share.test.ts`
    Vitest scan with three sub-rules:
    - Forbid property AND method declarations named `exportMetadata`,
      `remotionMetadata`, `renderManifest`, `exportCaptions`,
      `exportAssets`, `exportAudio`, or `videoDuration` on the
      `SceneModule` interface (`src/runtime/scene.ts`) or the
      `CompositionEntryOverride` interface
      (`src/runtime/composition.ts`). Property-name extraction covers
      identifier, string-literal, and computed-string-literal forms
      so a `['exportMetadata']: ...` member cannot escape.
    - Forbid parallel scene/composition schema declarations across
      every binding shape (`interface`, `type`, `const`, `let`,
      `var`, `class`, `function`, `enum`, destructured-binding,
      for-loop-header, import) anywhere under `src/**/*.ts`.
      Forbidden names: `ExportScene`, `RenderScene`, `SceneDTO`,
      `ExportComposition`, `RenderManifest`, `ExportSceneSchema`,
      `ExportCompositionSchema`, `ExportSceneDTO`,
      `ExportCompositionDTO`, `ExportSceneInput`,
      `ExportCompositionInput`, `ExportCompositionManifest`, plus
      the canonical names `SceneModule`, `CompositionManifest`,
      `CompositionEntry`, and `CompositionEntryOverride`. The
      canonical names carry path-AND-kind exemptions: only
      `interface SceneModule` and `type SceneModule = ...` are
      allowed at `src/runtime/scene.ts`; only `interface` / `type`
      declarations of `CompositionManifest`, `CompositionEntry`, and
      `CompositionEntryOverride` are allowed at
      `src/runtime/composition.ts`. Value-level declarations of any
      canonical name even at the canonical path are flagged.
      Consumer-side imports of a canonical name (un-renamed) whose
      specifier path-resolves to the canonical declaration site are
      exempt; imports from any other path AND any rename
      (`import { Foo as SceneModule }`) are flagged because the
      local binding shadows the canonical name with whatever the
      source actually exports.
    - Forbid the same export-metadata field AND method names on
      scene-module and composition-entry object literals (the actual
      authoring surface under `src/scenes/**/*.ts` and
      `src/compositions/**/*.ts`). `assertSceneModule()` accepts
      unknown keys at the value level, so the structural defense
      lives in source policy. Binding-shape detection covers: direct
      `: SceneModule` / `as SceneModule` / `satisfies SceneModule` /
      legacy type assertion; composition-manifest array entries
      (`const m: CompositionManifest = [{ id, exportMetadata }]`);
      function-return SceneModule (`function makeScene(): SceneModule
      { return {...} }` and arrow `(): SceneModule => ({...})`);
      intersection types (`SceneModule & Extra`); and file-local
      aliases (`import { SceneModule as Module }`, `type Module =
      SceneModule`, chained type aliases). Spread assignments
      (`{ ...extra }`) and opaque computed keys (`{ [key]: ... }`
      where `key` is not a static literal) inside a scene-shaped
      literal are structurally banned because their forbidden-field
      content cannot be statically classified.
  - Line-scoped `// PUL-A010-allow: <reason>` exemptions are honored
    via the shared `collectLineExemptions` helper. Empty rationales
    and markers hidden inside string literals are rejected.
  - No production source change: the runtime already routes every
    scene and composition metadata reference through the single
    canonical declaration sites; the gate locks the invariant in.
  - References: ADR-002 (scene/composition model), ADR-006 (Remotion
    as a parallel export path), PUL-A004's runtime-core import ban,
    and the design preflight at
    `docs/design/pul-a010-live-export-metadata-preflight.md`.
