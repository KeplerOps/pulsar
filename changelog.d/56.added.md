PUL-A008 mode-dispatch-in-core gate. Workbench mode dispatch is
structurally pinned to the runtime core (`src/runtime/navigation.ts`
and `src/runtime/scene-loader.ts`); scene modules under
`src/scenes/**/*.ts` may not branch on workbench mode literals.
  - New `tests/runtime/policy-a008-mode-dispatch.test.ts` Vitest
    source scan over `src/scenes/**/*.ts` flagging two AST shapes:
    `BinaryExpression` `===` / `!==` against a `NAVIGATION_MODES`
    string literal where the other operand is a `.mode` / bare-`mode`
    read; and `SwitchStatement` whose discriminant is `.mode` /
    bare `mode` with a `case '<NAVIGATION_MODES member>':` arm. The
    set of forbidden mode literals is imported live from
    `src/runtime/navigation.ts` so the gate extends automatically
    when `NAVIGATION_MODES` grows. A line-scoped
    `// PUL-A008-allow: <reason>` exemption covers the narrow
    scene-owned suppression case the preflight names (e.g.,
    deterministic randomness under `mode=screenshot`); empty rationales
    and markers hidden inside string literals are rejected. The runtime
    core is exempt by scope — it IS the dispatch boundary.
  - No production source change: the existing three scenes
    (`placeholder.ts`, `browser-support-fixture.ts`,
    `dom-css-accessibility-fixture.ts`) already consume
    `ctx.mode` only as a `NAVIGATION_MODES.includes(...)` validation
    guard with no mode-literal branches.
