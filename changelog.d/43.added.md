PUL-Q004 resource cleanup completeness source-policy gate. A new
Vitest scan at `tests/runtime/policy-q004-resource-cleanup.test.ts`
walks `src/scenes/**/*.ts` and flags scene-authored constructions
that bypass the runtime's activation-scope cleanup discipline:
global event-listener attach / detach calls
(`document.addEventListener`, `window.addEventListener`,
`globalThis.addEventListener`, `self.addEventListener`,
`global.addEventListener`, and their `removeEventListener`
siblings — directly, through global wrappers, and via
string-literal subscripts); DOM observer constructions
(`new MutationObserver`, `new IntersectionObserver`,
`new ResizeObserver`, `new PerformanceObserver` — including
wrapper-rooted forms and bare-identifier alias reads); and
prototype monkey-patches on `EventTarget`, `Element`, `Node`,
`Document`, `Window`, and `HTMLElement` (assignments to
`<root>.prototype.<member>`). Scenes must instead route DOM
through `ctx.stage`, audio through `ctx.audio`, timeline state
through `ctx.gsap`, and bind any necessary listener to the
navigation `AbortSignal`. The gate reuses `tests/runtime/source-policy.ts`
(AST walker, access-path resolution, line-scoped exemption parser)
so it plugs in alongside the existing PUL-Q001 / PUL-Q003 /
PUL-Q007 / PUL-A001..A006 gates. `// PUL-Q004-allow: <reason>`
opts a single line out for documented exceptions. The runtime
tree (`src/runtime/**/*.ts`) — which legitimately uses
signal-bound `addEventListener` across `audio.ts`, `presenter.ts`,
`navigation.ts`, `scene-loader.ts`, `timeline.ts`, and
`audio-unlock-dom.ts` — stays out of scope by design, with a
boundary-pinning test that asserts the scenes walker never pulls
in runtime files.
